# 灵感（Inspire）视图 — 设计

> **状态（2026-11-18）**：**已完成**。实现落在 `views/InspireView.vue` + `components/workspace/inspire/` +
> `stores/inspire.ts` + `composables/useMusicSource.ts`，`vue-tsc` 与 `vite build` 均通过；深浅色 / 中英文 /
> 空态 / 生成中 / 播放态已在浏览器预览里逐屏核对。与设计的偏差见文末「实现记录」。

## 1 背景

现在「写歌 / 云端音乐」藏在右侧面板的 AI 卡片里：进去一层卡片、再进一层表单，生成完只留一句 toast
和工程里的一条轨道。用户想要的是 SUNO 那种**一眼看到全部成品**的工作台：左边写、右边听。

参考物是 SUNO 的生成页（左创作面板 + 右作品列表）。**只借版面结构，不借它的商业 UI**：
点赞 / 点踩 / 分享 / 「Upgrade for full song」/「···」菜单一律不要；那里放**这条音频的播放进度条**。

## 2 目标与非目标

**目标**

- 顶栏最左新增第 5 个视图「灵感」，整页工作台，天然没有底部窗格。
- 左侧创作面板：模式（简单 / 进阶）、模型、风格描述、歌词（进阶）、时长/种子/步数（进阶）、生成。
- 模型下拉**复用 AI 写歌那一份列表**：本地权重 + 云端已配置服务 + 「设置音乐 API…」。
- 右侧生成记录：按日期分组；每行波形缩略 + 标题 + 模型徽章 + 描述 + **可拖动播放进度条**。
- 真实接通：本地走 YuE2/ACE-Step 任务，云端走既有 cloud-music；Audio 真实播放。

**非目标（v1 明确不做）**

- 参考音频 / 翻唱 / 续写、LoRA 音色、歌声合成。
- 搜索、筛选、批量选择、分页、发布分享、AI 封面图。
- 侧栏内嵌：灵感页是整页视图，不接管编排页左侧音轨栏。

## 3 位置与外壳

- 路由 `/inspire`（`views/InspireView.vue`），顶栏胶囊 `navItems` 首位。
- 胶囊原来把格数与滑块宽度写死 4：改成由 `navItems.length` 驱动（`--nav-count`），加视图只改数组。
- **外壳与其它视图完全一致**：左侧音轨栏（连同它的品牌区 logo + 「AI DAW」）、顶栏的工程名 / 视图胶囊 /
  动作区、右侧检查器面板、底部走带条全部照常渲染。灵感页**不是**焦点页——只有设置页才让出左右两栏。
- 唯一的差别是**下窗口**：它只长在 `ArrangeView` / `EditView` 里，所以「无需下窗口」是结构自然结果，不做开关。
- `ToolDock`（鼠标模式浮岛）本来就只在编排/编辑出现，无需改。

## 6 数据与播放

新 store `stores/inspire.ts`：

- `items`：生成记录，持久化到 localStorage（键 `ai-daw-inspire`，上限 50 条，倒序）。
  字段：`id / title / prompt / lyrics / model（徽章文字）/ source（local|cloud）/ path / seconds / createdAt / hue`。
- `craft`：在跑的那一次生成（提交时的 prompt / lyrics / 模型 / 来源），给「骨架行」与落库用。
- 播放：`readImportFile(path)` 拿字节 → `Blob` → `objectURL` → `new Audio()`。按 item 缓存 URL，
  切换 / 移除时释放；同一时刻只播一首；`requestAnimationFrame` 推进进度（`timeupdate` 只有 4 Hz，会一顿一顿）。

记录写入时机：本地订阅 `onYueJobEvent`，`state === "done"` 时用 `job.audio` / `job.seconds` 与
提交时抓的元数据配对；云端 `cloudMusic.generate()` 返回即写（它自带 path / duration / model）。

## 7 生成链路

提交时按模型 id 分派：`cloud:<providerId>` → `cloudMusic.generate`，否则本地
`yue.compose`（`name` 用标题，`after_track = null` 追加到末尾）。

- 本地缺引擎：弹 `EngineSetupDialog`（强制不可关，选一份去下）；缺权重：`useModelDownloadPrompt`
  后台下载（不跳页）；引擎没起：自动 `start()` 并等 `ready` 后继续——不让用户点两次。
- 云端没配置服务：下拉里的「设置音乐 API…」直接跳设置页音乐分区。
- 失败：状态行原样显示后端给的错误，不弹商业式弹窗。

## 8 视觉决定

- **波形缩略当封面**：没有封面图生成，也不该用假图。`audioWaveform` 取包络画 canvas，按路径缓存。
- **轨道色着色**：记录用工程里那条轨道的色相（`utils/trackColor`），列表与编排页的轨道配色对得上。
  这是这个 DAW 该有的身份识别方式。
- 深浅色走既有 `--md-*` token，不新造颜色；进度条用 `--md-primary`，轨道 4px（hover 6px）。
- 时长等宽数字；标题走 `text-title-sm`，描述一行省略号。动效沿用 `m3-rise`。

## 9 实现记录（与设计的偏差）

实现时踩到 / 改掉的东西，按重要性排：

1. **进度条不只靠 rAF**。`requestAnimationFrame` 在后台标签页、隐藏窗口（以及无头浏览器里）会被停掉，
   只靠它推进的话「声音在走、进度条冻住」。现在 `timeupdate`（4 Hz）兜底、rAF 负责顺滑。
2. **自动播放被拦时说人话**。`play()` 抛 `NotAllowedError` 时浏览器原文是一个带 google 链接的英文句子，
   对用户没有意义；现在换成「浏览器拦下了这次播放：再点一下播放键」。
3. **播放错误横幅放在列表顶部**，不放滚动区末尾——生成失败与播放失败是两件事，用不同的底色区分。
4. **创作面板固定宽度**（424px，两档断点收窄）。`flex: 0 0 clamp(...)` 在实测里被浏览器当成非法值忽略，
   面板会塌到内容宽度（~280px），输入框一行一个字。
5. **多行输入用 `m3-textarea` 而不是 `m3-input`**。后者是 34px 高的胶囊（`border-radius: 999px`），
   套在 textarea 上会切掉首尾字符、显示成一块怪异的药丸。
6. **浏览器预览的假音频改成一份真 WAV**（`api/mock.ts` 的 `readImportFile`）。预览模式原来回空字节，
   「读音频 → 播放」这条链在 `npm run dev` 里根本走不通；现在能真的听、能真的拖。
   顺带让 mock 的写歌任务回一条音频路径，于是「生成 → 记录 → 试听」在预览里能整条跑通。
7. **列表记录与工程的色相对应**靠 `hueOf()` 在渲染时查工程轨道（按音频路径），而不是落库时快照色相——
   轨道被删 / 颜色随轨道数变化时列表跟着变，不会定格在旧颜色。
8. **Blob URL 有上限（24 条）且不回收正在播放的那条**；记录被删 / 列表清空时连播放器一起摘下。

9. **收纳进标准外壳后的宽度**（第一版把左右两栏藏了，用户要求与其它视图统一，于是两栏回来）：
   中栏在 1440 窗口下只剩 ~840px。创作面板改成 `width: clamp(300px, 42%, 424px)`
   （按**中栏**比例，不是视口——`flex: 0 0 clamp()` 会被浏览器当非法值丢掉），
   记录列表用 `container-type: inline-size` + 容器查询收封面与内边距，行内改成「徽章先缩、标题优先」。
   1440 下实测：面板 352 / 列表 486 / 标题可用 212px（改之前标题只剩 70px）。
