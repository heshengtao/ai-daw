# 数据目录：安装时选择 + 设置里迁移

> 2026-11-01。目标：模型 / 运行时 / 插件 / AI 产物不再只能放在系统盘（Windows 的
> `%APPDATA%\com.aidaw.app`），安装时可指定，装好之后也能在设置里整体搬走。

## 背景

Tauri 的 `app_data_dir()` / `app_config_dir()` / `app_cache_dir()` 是按 bundle id 算出来的
固定路径，应用里原先有二十多处直接调用。模型（YuE2 3B 一个就 7 GB）、ONNX Runtime、
Demucs、SoulX 权重、`local-ai/` 下的分离/换声 WAV 加起来很容易到 30 GB，系统盘说满就满。

只把「新下载」改到别处不够：已经装好的用户需要把现有数据整体搬走，而且不能把正在使用的
插件 DLL / 日志 / 会话缓存删坏。所以方案分成三层：**解析**、**迁移**、**引导**。

## 1. 路径解析（`src-tauri/src/paths.rs`）

所有数据 / 配置 / 缓存路径都改走 `paths::data_dir()` / `config_dir()` / `cache_dir()`，
不再直接调用 Tauri 的固定目录。解析优先级：

| 优先级 | 来源 | 典型场景 |
| --- | --- | --- |
| 1 | `--data-dir <path>` / `--data-dir=<path>` | 便携版、自动化测试 |
| 2 | 环境变量 `AIDAW_DATA_DIR` | 绿色版启动脚本 |
| 3 | `<默认配置目录>/data-dir.json` | 设置页迁移后写的指针 |
| 4 | `HKCU\Software\AI DAW\DataDir` | NSIS 安装器选目录 |
| 5 | Tauri 默认目录 | 没做任何选择的用户 |

关键点：

- **指针文件留在默认配置目录**。数据目录搬走之后，它是启动时唯一稳定的锚点；文件内容
  是 `{"path":"D:\\AI DAW Data","previous":"C:\\Users\\…\\com.aidaw.app"}`。
- **本进程的目录在启动时冻结**（`EFFECTIVE: OnceLock`）。迁移只写指针，不改变当前进程
  实际使用的目录；否则会出现「日志还写旧目录、模型却去新目录找」的撕裂状态。重启后新
  进程才按指针切过去。
- 覆盖目录生效时 `config_dir` 与 `data_dir` 同根、`cache_dir = <root>/cache`：模型、运行时、
  插件、日志、历史一起搬，不会留一半在 C 盘。
- Windows 上 `app_data_dir` 与 `app_config_dir` 本来就是同一个目录，`sources()` 会去重，
  不会复制两遍。
- `cli-path` / `mcp-url` 这类**给外部工具按 bundle id 找的发现文件**刻意留在默认配置目录
  （它们只有几十字节）；数据目录搬走后，别的 harness 仍然找得到。

## 2. 迁移（设置页「存储」）

`data_dir_migrate(target)`：

1. 校验目标是绝对路径、不是当前目录的父/子目录、**必须是空文件夹**（避免覆盖已有文件）。
2. 扫描数据 / 配置目录的总字节数，发 `app://data-dir` 进度事件（约 120 ms 一次）。
3. 递归复制。跳过：
   - `logs/`：正在写、可重建，复制过来也没意义；
   - `cache/`：可重建；
   - `data-dir.json`：指针不能跟着搬，否则新目录会指向自己。
   - 符号链接 / 目录联接：迁移不是备份，不跟着链接跑。
   单个文件复制失败（被占用等）只跳过该文件，不让整次迁移失败。
4. 原子写指针（临时文件 + rename），并同步写注册表（失败只记日志，指针才是权威）。
5. **重写目标目录里 `.json` 状态文件中的旧绝对路径**（工程会话、历史快照、插件
   `manifest.json`、插件 catalog 缓存……）。JSON 文本里的反斜杠是双写的，所以两种写法
   都替换；这是迁移后「插件还在、工程素材还在」的关键。
6. 返回「当前仍在旧目录、`next` 是新目录、需要重启」的状态。

数据目录**之外**的用户工程文件无法在迁移时逐个改写，所以加载素材时再做一次透明重映射
（`paths::remap_legacy`）：指针里保留历次数据根目录（`legacy`），旧前缀 + 新目录里确实
存在同一文件时才改写。清理旧目录不会删掉 `legacy`，所以工程以后仍能打开。

**旧目录不在进程运行中删除**：插件 DLL、正在写的日志、会话缓存都还开着。设置页在重启后
显示「旧数据」区，用户点「清理旧目录」才递归删除旧目录内容；如果旧目录是默认配置目录，
会保留指针文件本身。删除失败的条目跳过并记日志（杀毒 / 索引占用很常见），下次可以再点。

设置页位置：**设置 → 存储**。显示当前位置、来源、占用大小、默认位置；「选择目录并迁移」
走系统文件夹选择框 + 二次确认；迁移中显示进度条；迁移完成显示「立即重启」。

## 3. 安装时选择（NSIS）

`src-tauri/nsis/data-dir-hook.nsh` 通过
`bundle.windows.nsis.installerHooks` 挂到 `NSIS_HOOK_PREINSTALL`：

- 只在**首次安装**（注册表里还没有 `DataDir`）且非静默安装时弹 `nsDialogs::SelectFolderDialog`；
- 用户选的目录写进 `HKCU\Software\AI DAW\DataDir`，应用启动时按第 4 优先级读取；
- 取消 / 静默安装什么都不写，回落到系统默认目录；
- 卸载不删用户数据（模型和工程缓存可能还有用）。

注意：CI 同时产出 `msi` 与 `nsis` 两种安装包，**这条安装向导只覆盖 NSIS `-setup.exe`**。
MSI（WiX）要同样效果需要另写 WiX UI 扩展；已安装用户仍可用设置页迁移，不依赖安装器。

## 4. 代码地图

| 位置 | 作用 |
| --- | --- |
| `src-tauri/src/paths.rs` | 优先级解析、冻结、指针读写、迁移/清理、进度事件、三个 Tauri 命令 |
| `src-tauri/src/lib.rs` | `paths::init_from_args()`（最早）、命令注册、其它路径调用改走 `paths` |

| `src-tauri/nsis/data-dir-hook.nsh` | 安装时选目录 |

| `src/api/tauri.ts` / `types.ts` / `mock.ts` | 前端命令封装与浏览器预览假数据 |

## 5. 已知限制

- 迁移前不预检磁盘剩余空间；空间不够时会在复制途中报错（指针不会写，旧数据不受影响）。
- 迁移是「复制」，需要目标盘有与源目录等量的空闲空间；完成后旧目录要手动/点按钮清理。
- 迁移期间应用仍可编辑，但新产生的文件写在旧目录，重启后才会从新目录继续。
- `--data-dir` / `AIDAW_DATA_DIR` 是只读覆盖：设置页会禁用迁移按钮并提示改启动参数。
