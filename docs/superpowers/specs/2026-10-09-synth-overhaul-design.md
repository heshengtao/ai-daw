# 内置合成器改造：音源能力 + 内置效果器 + 8 类预设

> 状态：**已完成**（2026-10-09）。分四个阶段落地，每阶段都跑了全量测试与真机验证。

## 1 缘起与目标

原来的内置合成器只有减法合成（DCO + 副振 → HPF → SVF → VCA，18 个参数），
出厂预设 24 条挤在 6 个类别里，而且**引擎没有任何内置效果器**——铺底/弦乐/管乐/音效
这些最需要空间感的音色只能干着听。目标：

1. 音源能力扩到能支撑 8 类音色（8-bit 键盘 / 吉他 / 贝斯 / 鼓组 / 弦乐 / 管乐 / 铺底 / 音效）；
2. 补上内置延迟与混响，并且**预设能自带效果链**；
3. 出厂预设重写为 **8 类 × 4 = 32 条**，8-bit 是第一类。

用户已确认：**放弃老工程兼容**（软件尚未发布），可以自由重排参数表、替换预设 id、改默认模板。

## 2 决策：一个合成器 + 更多原子，而不是多个引擎

用户列了减法 / FM / 波表 / 加法 / 物理建模 / 颗粒六种方法。做成「每个预设一个引擎」会让参数表、
状态序列化、面板三处同时爆炸。改为**保留单一声部架构，补齐能让 8 类音色都成立的原子**，
每类音色 = 一组参数配方（与仓库既有「预设不是另一套 DSP」的立场一致）。

| 方法 | v1 怎么来 | 诚实说明 |
| --- | --- | --- |
| 减法 | 原有 | 真做 |
| FM | 新增调制器做**相位调制** | 两算子，真做；不是多算子算法 |
| 波表 | 脉冲波（12.5/25/50%）+ 位深压碎 | **近似**，无波表扫描 |
| 加法 | 正弦 + 调制器产生泛音 | **近似**，无独立分音 |
| 物理建模 | 噪声起振 + 音高包络 + 快衰减 | **近似**，非 Karplus-Strong |
| 颗粒 | 位深/采样率压碎 + 失谐 | **近似**，非真颗粒 |
| 噪声 / 调制 / 效果 | 噪声源、LFO、延迟、混响 | 真做 |

## 3 参数表：18 → 26（**追加在末尾**）

| id | 范围 | 默认 | 作用 |
| --- | --- | --- | --- |
| `noise` | 0..1 | 0 | 与振荡器**混合**（1 = 纯噪声）。鼓的镲/军鼓、管乐气息、拨弦起振 |
| `crush` | 0..1 | 0 | 位深 16→3 bit + 采样率 1×→32× 降采样。8-bit、音效 |
| `detune` | 0..1 | 0 | 第二振荡器 +0..+2%（≈34 音分），两者各半。弦乐、铺底、宽主音 |
| `fm` | 0..1 | 0 | 载波相位调制量 0..4 rad |
| `fmRatio` | 0.5..8 | 2 | 调制器频率比 |
| `pitchEnv` | 0..1 | 0 | 起音从 +2 八度线性扫回 0。底鼓、音效、拨弦 |
| `pitchDecay` | 0..1 | 0.1 | 5 ms .. 2 s（指数） |
| `filterType` | 0..2 | 0 | 0=低通 1=带通 2=高通 |

追加而非插队：`load_state` 本来就「多出来的忽略、少掉的保持默认」，于是**状态短于当前参数表时
新参数保持默认**，不需要版本号。

**`noise` 是混合而不是相加**：`sig = sig*(1-noise) + white*noise`。闭镲需要 `noise = 1` 得到
纯噪声，相加的话永远混着振荡器。

**位深压碎放在滤波之后、VCA 之前**：保留数字硬边，而不是被滤波器抹平。

**每块一次的派生常量**：`voice::Block` 把滤波器阻尼、脉宽、FM/压碎/音高包络的系数算一次，
不再每采样重算（改版后每声部每采样要跑两个振荡器 + 一个调制器）。

## 4 内置效果器：新 crate `daw-party-effects`

- `Delay`：立体声，每通道一条延迟线，**分数延迟 + 线性插值**（拧时间旋钮是连续滑音而非跳变）。
- `Reverb`：施罗德网络（4 并联梳状 + 2 串联全通 / 通道），经典 Freeverb 刻度，右通道偏移
  23 采样取立体声宽度。`size` 调**反馈量**而不是缓冲长度，所以不需要重新分配。

两者都只在 `prepare()` 里按采样率分配延迟线（`prepare` 只在建宿主时调用，不在音频回调里），
`process` 内不分配。`reset()` 清空延迟线——**暂停即静音**之后不留尾音。

注册为 `builtin.delay` / `builtin.reverb`，前端 `BUILTIN_PLUGINS` 里有对应条目，
参数表预填进 `BUILTIN_PARAMS`，于是**自动出现在效果器选择列表里**，并复用通用参数面板。

## 5 预设自带效果链

- `FactoryPreset` 增 `effects?: EffectSpec[]`。
- 引擎已有 `execute_all(commands, actor)`：N 条命令 = 一次应用、一次广播、**一个撤销步骤**
  （`set_params` 就是这么做的）。因此**不需要新的 IPC 契约**：新命令 `apply_preset` 内拼
  `[SetParam × n, RemoveEffect × n, AddEffect × m, SetEffectParam × k]` 一次交给它。
- Tauri 命令与 MCP 工具 `apply_preset` 共用内核 `apply_preset_inner`（只有 actor 与广播方式不同）。
- **语义：预设 = 整套音色，切预设会替换该轨的效果链**。理由：切预设本来就会丢掉所有旋钮微调，
  丢掉效果微调是同一个契约。`stores/presets.ts::match` 因此也要连效果链一起比对，
  否则带效果的预设永远高亮不上。

## 6 预设清单（8 类 × 4）

| slug | 中文 | 4 条 |
| --- | --- | --- |
| `8bit` | 8-bit 键盘 | 主音 / 和弦 / 琶音 / 钟（**全干声**，芯片原味） |
| `guitar` | 吉他 | 民谣 / 电 / 闷音 / 泛音拨弦 |
| `bass` | 贝斯 | 低音 / 超低音 / FM / 弹拨 |
| `drums` | 鼓组 | 底鼓 / 军鼓 / 闭镲 / 通鼓 |
| `strings` | 弦乐 | 弦乐 / 拨奏 / 大提琴 / 颤音 |
| `winds` | 管乐 | 长笛 / 单簧管 / 萨克斯 / 铜管 |
| `pad` | 铺底 | 铺底 / 温暖 / 玻璃 / 人声 |
| `fx` | 音效 | 上升音 / 抖颤低音 / 氛围持续 / 短路点音 |

效果分配：鼓带短房间、吉他/贝斯基本干声、弦乐/管乐/铺底/音效带混响（铺底与音效可再带延迟）。

### 默认模板那 5 条是干声（刻意的）
`STARTER_TRACKS` 的 plugin_id 必须是**引擎注册表认得的 id**，否则新建工程就是「缺失插件」占位。
注册表补丁只能带参数、带不了效果链，而前端同名条目必须与它一致（否则「默认模板的听感」与
「点一下那个垫子的听感」会对不上）。因此这 5 类的**第 1 条刻意不带效果**，湿版本是第 2..4 条：

| 默认轨道 | id | 取哪一类 |
| --- | --- | --- |
| 主旋律 | `builtin.synth.lead` | 8bit[0] |
| 和弦 | `builtin.synth.strings` | strings[0] |
| 低音 | `builtin.synth.bass` | bass[0] |
| 鼓组 | `builtin.synth.drums` | drums[0] |
| 铺底 | `builtin.synth.pad` | pad[0] |

其余 27 条只活在界面层（轨道始终挂在 `builtin.synth`，只记参数差异）。
`LEGACY_SYNTH_IDS` 随之改名为 `ENGINE_PRESET_IDS`（就是这 5 条）。

## 7 验证

**自动化**（`cargo test --workspace` → 182 通过，改前 157）：
- 合成器 10 条**量化**断言：`noise=1` 过零率 >8× 正弦；`crush=1` 电平步长恰好 1/8；
  `detune` 产生可测拍频（窗口峰值比 <0.5，关掉则 >0.9）；`fm` 过零 >2×；`pitchEnv`
  前段过零 >2× 后段；高通把低音 RMS 压到低通的一半以下；**新参数在默认值下逐样本不改变输出**。
- 效果器 10 条：`mix=0` 逐样本等于输入；延迟回声落点误差 ≤2 帧、反馈越长尾巴越长；
  混响尾音单调衰减且无 NaN、左右去相关；`reset` 清空尾音。
- 3 条走**真实渲染路径**：混响在干声已静音处仍有余量；延迟在音符结束后产生递减回声。
- **零分配门禁把两个效果器挂进轨道效果链**（非默认参数）后仍然通过——不加这一步，
  门禁根本覆盖不到新增的回调代码。
- 交叉校验：脚本比对 Rust 与 TS 两侧 5 条双注册预设的参数，逐字段一致。

**真机（MCP 驱动跑起来的应用）**：
- 默认模板 5 条轨道解析到 5 个已注册 id（不是占位）。
- `apply_preset` 12 个参数 + 效果链一次写入；效果链**替换**语义确认。
- 底鼓：音符 36（65.4 Hz）→ 频谱峰 **65 Hz**，峰值 −1.45 dBFS。
- 闭镲（隔离后）：前 3 频点 4759 / 1292 / 20629 Hz，无基频峰；对照正弦低通在同轨的峰是
  **517 Hz**（音符 72 = C5 = 523 Hz），>4 kHz 只有 −134 dB。
- 同一音符同一铺底：干声 RMS −19.09 dBFS → 带混响 −17.92 dBFS。

**界面（浏览器 + 真实 dev server）**：8 个类别 chip 一行放得下（465/866 px，不换行）；
滤波类型三段按钮；高级区 7 个分组、16 个旋钮（含全部新参数）；设备 scrollHeight == clientHeight（不溢出）。

**未验证 / 只能人工**：32 条预设在真机上**逐条听感**（音色好不好听是主观判断，需要你的耳朵）。
预设在 `src/data/plugins.ts` 里是纯数据，改起来很快。

## 8 已知取舍

- 波表/加法/物理建模/颗粒都是**近似**（见 §2 表），不是真实现。
- 「上升音 Riser」用的是**长起音 + 滤波包络**把滤波器打开，而不是一次性上行扫频包络
  （引擎只有音高下扫包络）。听感成立，但严格说不是「扫频器」。
- `crush` 关闭时整段跳过，保证 `crush = 0` 与改版前逐样本一致。
- 自存预设（用户预设）只存乐器参数，不带效果链。
