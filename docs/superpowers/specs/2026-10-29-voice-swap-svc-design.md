# 音色替换（SoulX-Singer-SVC ONNX）设计

- 日期：2026-10-29
- 状态：已完成（中文普通话人声；目标/参考都要求单声部人声）
- ONNX 导出与参考实现：`D:\AI\SoulX-Singer-SVC`（`tools/sxpipeline.py` / `tools/export_onnx.py`）
- 上游模型：SoulX-Singer 的 SVC 微调权重（Apache-2.0，Soul AI Lab）
- 模型仓库：[Hugging Face](https://huggingface.co/ailm32442/SoulX-Singer-SVC-ONNX) / [魔搭](https://modelscope.cn/models/ailm32442/SoulX-Singer-SVC-ONNX)

## 1. 问题与目标

歌声合成（[`2026-10-28-singing-voice-design.md`](2026-10-28-singing-voice-design.md)）解决的是
「从零唱出一条人声」；但用户手里经常**已经有一段人声**，只想换音色：

> 选一条人声轨 + 一条参考声线 → 得到同旋律、同节奏、同咬字，但换成参考音色的新音频轨。

目标：

1. **本地、离线、ONNX**：不依赖云、不要 API Key，权重按需下载，与 Basic Pitch / HTDemucs /
   歌声合成同一套 `local-ai` 与「管理器 → 模型」。
2. **旋律由目标音频决定**：F0 从目标音频里提，参考声线只提供音色；不改谱、不要求 MIDI。
3. **进同一条命令管线**：产物是普通音频轨 + 普通音频片段，落在源轨下面，一次撤销可回退。
4. **国内外双源**：魔搭 + Hugging Face，逐文件 sha256，失败自动换源。
5. **不引第二个模型**：SVC 已经 2.4 GB，F0 用纯 DSP，不再挂 RMVPE。

非目标：

- 实时替换（离线渲染；10 秒在 CPU 上约 1–2 分钟）。
- 复音 / 混音素材的自动人声分离（先跑「音源分离 → 人声」是推荐流程）。
- 自动移调匹配音域（`pitch_shift` 由用户显式给）。
- 纯 FP16 档（DiT 对 FP16 极敏感，导出的 `onnx_fp16` 音质只有 2.3 dB SNR，不作为产品档）。

## 2. 为什么是这 7 张图

| 文件 | 作用 | fp16_hq 大小 |
| --- | --- | --- |
| `mel.transform.onnx` | 24 kHz 波形 → 标准化 mel（128 维） | 15.3 MB |
| `whisper.frontend.onnx` | 重采样 + log-mel + 6 层 whisper encoder（30 s 窗口） | 85.1 MB |
| `f0.encoder.onnx` | 50 fps F0（Hz）→ 512 维逐帧嵌入，支持半音移调 | 0.74 MB |
| `cond.emb.onnx` | 帧级条件 512 → 1024 | 1.05 MB |
| `dit.step.onnx` | flow-matching 单步（DiT，442 M 参数） | 1.77 GB |
| `vocoder.backbone.onnx` | Vocos：128 维 mel → 1922 维系数 | 510 MB |
| `vocoder.istft.onnx` | 系数 → 24 kHz 波形（等价 `conv_transpose1d`） | 14.8 MB |

全部是**自足 ONNX**（权重内嵌），不依赖 `.onnx.data`。

两档精度：

| 档 | 目录 / 清单 id | 体积 | 说明 |
| --- | --- | --- | --- |
| `fp16_hq`（推荐） | `soulx-svc-fp16hq` | 2.23 GiB | 声码器 / 条件用 fp16，**扩散步保留 fp32** |
| `fp32` | `soulx-svc-fp32` | 2.71 GiB | 全 fp32；扩散步与 hq 档字节相同 |

区别只在 `vocoder.backbone.onnx` 与 `cond.emb.onnx`。纯 FP16 的 DiT 在 32 步积分 + CFG=3
下会把舍入误差放大，和 PyTorch 只有 2.3 dB SNR，因此不提供该档。

## 3. 推理流程

```
目标音频（单声道 24 kHz）
  → YIN F0（50 fps，清音 0）                  ← 纯 DSP，见 §3.1
  → 按 F0 切段（>30 s 才切；15–30 s/段，1 个切点重叠）
  → 每段：f0_encoder(目标 F0, pitch_shift)
        + whisper.frontend(目标波形) → 逐帧拼到段长
  → 条件 = cond.emb([参考段 | 目标段] 的 512 维特征)

参考音频（单声道 24 kHz）
  → 自动挑最像人声的 10 秒
  → mel.transform → prompt mel（≤500 帧）
  → f0_encoder(prompt F0, 0) + whisper.frontend(prompt) → prompt 特征

flow-matching Euler 采样（32 步，t=(step+0.5)/32）
  xt = 标准正态噪声（1, T_gt, 128）
  cond 分支：xt_input = [prompt mel | xt]，mask 全 1
  uncond 分支：xt_input = xt，cond 全零，mask 目标段 1
  v = cond + 3.0 × (cond − uncond)
  rescale：v ← v · std(cond) / std(v)；再 0.75·rescale + 0.25·v
  xt += v × dt
  → vocoder.backbone → vocoder.istft → 24 kHz 波形
  → 裁 / 补到该段原始长度，只把「核心段」（去掉重叠）写回输出

输出整段：推理前按「目标有声帧 RMS → −20 dBFS」做一次标量归一化（±24 dB、峰值保护）；
     输出逐帧（50 ms 帧 / 25 ms 跳步）把包络对齐到**目标**，再整轨兜底（±6 dB），
     最后前视限幅（−1 dBFS 起、5 ms 前视、80 ms 释放、绝对上界 −0.45 dBFS）
段与段之间：20 ms 交叉淡化（后一段的推理段本来就覆盖前一段的整段核心）
```

**与歌声合成的区别**：SVC 每步**没有**动态阈值（参考实现也没有），CFG 后处理只有 rescale
（权重 0.75；SVS 是 0.7）。prompt 的 cond 段填 0、只通过 xt 前缀进入模型，与参考实现一致。

### 3.1 F0：为什么自己写 YIN

官方流程用 RMVPE（神经网络）出 F0。本应用选择不引第二个模型：

- SVC 已经 2.4 GB，再挂 100 MB 级模型只为 20 ms 一帧的音高不划算；
- 纯 DSP 在**单声部人声**上足够准（见 §6 的实测）；
- 少一个模型 = 少一份下载源、许可与失效面。

实现（`crates/local-ai/src/svc/f0.rs`）：

1. 按 50 fps 分帧（24 kHz / hop 480），帧长 2048（85 ms）。
2. FFT 算 YIN 差分函数 `d(τ) = Σ(x_j − x_{j+τ})²`（能量前缀和 + 互相关）。
3. 累积均值归一化 `d'(τ)`，取第一个 < 0.15 的谷；没有则取全局最小（仍须 < 0.4）。
4. 抛物线插值细化周期，转 Hz；清音 / 静音为 0。
5. **只修八度跳变**（与 ±2 帧中值差 > 600 音分才替换），保留颤音。

不加窗是刻意的：YIN 的差分函数要求自相关与能量前缀基于同一段原始采样，加窗会让两者对不上，
`d(τ)` 永远压不到阈值以下。

**素材要求**：目标与参考都应是单声部人声。混音里的鼓 / 和弦会让周期检测判错八度甚至完全
跑偏；界面说明与 MCP 描述都建议先做「音源分离 → 人声」。

### 3.2 电平与动态：为什么不再是「一个标量 + 软限幅」

2026-10-30 重做。旧后处理的问题是三件叠在一起：

1. **只有一个全局标量增益**（按整轨 RMS 求一个数）。它对齐的是「整轨平均响度」，
   **段内相对动态一点没动**——素材里大的地方照样大、小的地方照样小，所以听感是
   「音量不稳、忽大忽小」。
2. **0.65（−3.7 dBFS）起点的 `tanh` 软饱和**。这不是「只挡瞬态」：一个持续的大音量
   唱段整句都在阈值以上，整句被压 → 谐波失真，也就是「大的地方破」。
3. **为了补回限幅吃掉的 RMS 又继续加增益**（最多迭代 3 次、上限 +30 dB）。越补越把
   内容推进饱和区，形成「越补越糊」的正反馈。

现在的顺序（`crates/local-ai/src/svc/mod.rs`）：

| 步骤 | 参数 | 作用 |
| --- | --- | --- |
| 输入归一化 | 有声帧 RMS → −20 dBFS，±24 dB，峰值 ≤ −0.45 dBFS | mel / whisper 前端只认训练集的电平尺度；这一步**只乘一个标量**，不动动态 |
| 逐帧包络匹配 | 50 ms 帧、25 ms 跳步，`目标包络 ÷ 输出包络`，±24 dB，压 10 ms / 抬 60 ms | 真正把**相对动态**还原成目标的样子；先落第一帧，避免文件开头渐强 |
| 整轨兜底 | ±6 dB | 只处理逐帧增益被夹住的极端素材 |
| 前视限幅 | −1 dBFS 起、5 ms 前视、80 ms 释放、上界 −0.45 dBFS | 峰值走**限幅**而不是饱和；对 0.95 的正弦只整体缩 0.55 dB，峰均比仍是 √2（不变形） |
| 段间交叉淡化 | 20 ms | 后一段的推理段本来就覆盖前一段的整段核心，把两份渲染混合，消掉接缝台阶与咔哒 |

顺序是**先对齐、后限幅**：限幅带走的那点 RMS 正是超过 −1 dBFS 的峰值，不该再靠抬整体
增益补回来——那正是旧实现「越补越糊」的来源。

## 4. 模型分发

清单新增两条（`crates/local-ai/src/models/catalog.rs`）：

- `soulx-svc-fp16hq` / `soulx-svc-fp32`，`feature: "voice_swap"`，`bundled: false`，
  `dir: Some(...)`（组条目，整组齐备才算安装）。
- 每个文件都带 `sha256` 与 **HF + 魔搭双源**；HF 与魔搭的仓库目录就是导出的
  `onnx_fp16_hq/` / `onnx_fp32/`，下载器按网络偏好排序后逐文件校验。
- 多文件组落在 `models/<dir>/`，7 张图必须同目录（`ort` 的一次加载不用外部路径，但组语义
  保证「缺一张就不算装好」）。

## 7. 已知限制与取舍

1. **只适合单声部人声**。混音目标会得到跑调的 F0；先分离人声。
2. **F0 是 DSP 估计**，不是 RMVPE。清唱 / 干声上 95% 的帧在 50 音分内；换声区、气声、
   强颤音附近会有少量偏差。
3. **参考音频 ≤30 秒**：whisper 固定 30 s 窗口；实际只取最像人声的 10 秒。
4. **目标 >30 秒自动分段**：按清音段切、15–30 秒/段、1 个切点重叠；接缝处只写回核心段。
5. **处理的是整个音频文件**（与降噪 / 分离一致），片段窗口（`offset_frames` / `frames`）
   原样沿用，所以时间轴不受影响；但片段上的 `rate` / `pitch_semitones` 不参与推理。
6. **CPU 时间**：10.7 秒素材约 60–90 秒推理（模型加载另计 10–20 秒）。Windows 走 DirectML
   时取决于驱动；失败会回落 CPU。
7. **输出响度对齐目标**：推理前先把目标电平归一到固定量级；输出端**逐帧**把包络对齐到
   目标（这才是「大的压下来、小的抬上去」），再整轨兜底、前视限幅兜峰值。见 §3.2。
   SVC 在伴奏段更静，所以有声段允许比目标低 1–2 dB，整轨 RMS 基本一致。
8. **模型在清音 / 停顿处会输出纯数字静音**。实测两段真实素材里分别有 **27% / 21%** 的采样
   是精确的零（16-bit 文件里 < −90 dBFS 的部分也归零）。后处理无法凭空造出气声与房间底噪，
   所以停顿处听起来是「死寂」而不是「换了个人的呼吸」。可行后续：在模型输出为零而目标有
   能量的帧上，混入源素材的清音残响（音色不敏感），或换 seed 重跑该段。

## 8. 验证

- **F0 与 RMVPE 对拍**（`zh_prompt.mp3`，535 帧）：有声帧占比 78.3%（参考 77.2%），
  两者都有声的帧里 **95.2% 在 50 音分内**，中位误差 6.4 音分，无八度错误。
- **端到端**（fp16_hq，32 步，10.7 秒目标 + 5.1 秒参考，CPU）：输出 10.7 秒；
  对输出再提 F0 与目标对比，**94.7% 的帧在 50 音分内**（中位 6.9 音分），
  相邻帧音高跳变中位 3.6 音分；峰值 0.865、无 NaN。
- 单元测试：F0 帧数 / 正弦跟踪 / 静音 / 八度修正、分段长度与清音切点、RMS / 标准差、
  模型 id 与清单双源、YIN 帧格、输入归一化（轻 / 响 / 静音段不计入）、逐帧动态跟随
  （小声段与大声段各自对上、相对动态不被压平）、限幅透明性与不变形（0.95 正弦峰均比
  仍 √2）、单尖峰不压整轨、接缝交叉淡化无台阶。
- **长音频响度（4 分钟真实案例，旧后处理）**：按绝对峰值缩放时，192 秒处一个 34 dB
  峰均比的瞬态把整轨压到 **−34.2 dBFS**（目标 −21.3，差 13 dB）。改成「全局标量 + 软
  限幅」后得到 −21.2 dBFS、峰值 0.99，但动态没处理（§3.2 的三条问题）。
- **真实素材 A/B（2026-10-30，45 秒人声摘录，fp16_hq / 32 步 / CUDA，同一参考声线）**：
  指标是「输出 vs 源素材的帧电平」（100 ms 帧，只统计目标有声帧），与随机种子无关：

  | 指标 | 目标（原唱） | 旧后处理 | 新后处理 |
  | --- | --- | --- | --- |
  | 帧电平 90–10 分位动态 | 9.3 dB | 20.7 dB | **9.2 dB** |
  | 电平差中位 | — | −10.2 dB | **+0.1 dB** |
  | 电平差标准差 | — | 11.5 dB | **1.2 dB** |
  | 包络相关系数 | 1.00 | 0.23 | **0.975** |
  | 峰值 | −1.31 dBFS | −0.09 dBFS | −1.00 dBFS |
  | 超过 0.65（旧饱和起点）的时间 | 0.01% | 0.49% | **0.04%** |

  即：旧输出整体比原唱低 10 dB 且动态被放大一倍以上（正是「忽大忽小」）；新输出逐帧跟住
  原唱（±1.2 dB，1σ），相对动态**没有被压平**（9.2 vs 9.3 dB）。两边的输出是两次独立推理
  （种子不同），但「输出跟不跟得住源素材」这个指标与种子无关。
