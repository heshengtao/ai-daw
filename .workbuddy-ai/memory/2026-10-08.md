# 2026-10-08

## 技术选型建议评估（第三方"Sidecar + UAPMD + Open Audio Stack"方案核对）

对一份外部技术选型建议做了事实核对，并给出完善路线。**已核实的关键结论（后续可复用）：**

- **项目真实状态**：纯 **Apache-2.0**（`Cargo.toml` workspace + `NOTICE`），**没有 GPL**；前端是 **Vue 3 + Pinia + Tailwind**，不是设计文档里写的 React + `@m3e/react`；`crates/synth` 是手写合成器（只依赖 plugin-api），**不是 fundsp** —— 设计文档 `docs/superpowers/specs/2026-10-07-ai-daw-design.md` 已与实际实现漂移。
- **已有**：`crates/engine`（model / command+event 总线 / transport / schedule / player / render / wav，`#![forbid(unsafe_code)]`，cpal 走 `realtime` feature）、`crates/plugin-api`（自定义 `Plugin` trait ABI，process 签名仿 nih-plug/JUCE）、`crates/synth`、`src-tauri`（仅 get_project/add_track/set_tempo/clear_project/load_demo/render_preview/export_wav）。
- **尚无**：`host-vst3` / `ipc` / `analysis` crate；无 MCP；无插件扫描。
- **关键缺口**：引擎里的 cpal 实时宿主（`realtime.rs`、`AudioHost`）**未接上 UI** —— `src-tauri` 没有 play/pause/seek 命令，前端 `usePlayback.ts` 走的是"离线渲染 → Blob → `<audio>`"。

### 许可证事实（重点，勿忘）
- **Dhwani = GPL-3.0-only**（lib.rs 确认），不是建议所说的"Apache/MIT 双许可"；链接会传染整个 DAW → **不可用于本项目**。
- **ASIO SDK 现为 GPLv3（开源变体）或 Steinberg 专有许可** → 在 Windows 启用 cpal 的 ASIO 后端会破坏纯 Apache-2.0 分发。
- **truce-rack = MIT OR Apache-2.0**，纯 Rust（objc2 / clap-sys / vst3 / lilv-sys），CLAP+VST3 默认、AU/LV2 可选 → **最契合 `crates/host-vst3`**。
- **UAPMD 是 C++/CMake 工程**（MIT，opt-in 模块 Apache-2.0），不是 Rust；有 MCP + JS API + 远程进程扫描/延迟补偿/轨道冻结，但接入需 C++ FFI，与引擎 `#![forbid(unsafe_code)]` 冲突。
- **VST 3.8 SDK（2025-10）已转 MIT** → VST3 宿主 + Apache-2.0 开源可行（设计文档此判断正确）。
- `@open-audio-stack/core` 真实（npm，TS 5.x）可做插件商店；LSDJ（protocol-works/lsdj）确为 Tauri+Rust+ML sidecar 的实时 AI 乐器，可借鉴其 MCP/skills 层。

### 建议的完善路线（四阶段）
1. 补齐 v1：cpal 实时宿主接上 UI（play/pause/seek + 位置事件）；抽出 `crates/ipc` 作为 Command/Event 契约。
2. 插件托管：`crates/host-vst3` 基于 truce-rack，适配到既有 `Plugin` trait；先扫描+加载+通用参数+状态。
3. AI 层：`src-tauri` 内嵌 MCP（参考 LSDJ，AI 与人类共用命令总线）；`crates/analysis` 用 ebur128/rustfft 做响度/频谱闭环。
4. 生态与隔离：前端 `@open-audio-stack/core` 做商店 UI + Rust 侧安装；第三方插件上量后再拆 helper 进程做崩溃隔离（音频引擎本身不必拆进程）。
